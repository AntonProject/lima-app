Фактический ответ `GET /api/WorkDay/status`:

```json
{
  "is_started": false,
  "is_completed": false,
  "start_time": null,
  "end_time": null,
  "day_type_id": null,
  "day_type_name": null,
  "is_late": false,
  "duration": null
}
```

Фактические типы рабочего дня:

1. `Обычный день` — `Визиты к врачам и в аптеки`.
2. `Больничный` — `Не планируются визиты`.
3. `Работа в офисе` — `Административная работа`.

## Аудит реализации 2026-08-20

Этот раздел отражает фактический код и имеет приоритет над более ранними
галочками и открытыми вопросами выше.

### Реализовано

- [x] Feature flag, status и day types загружаются, типизированно парсятся и
  кешируются отдельно для пользователя.
- [x] Start/end используют геопозицию с fallback `0,0`, поддерживают online и
  optimistic offline-сценарий с FIFO-очередью.
- [x] Есть локальная защита от повторного offline-start после уже завершённого
  дня; online-сценарий показывает текст ошибки API.
- [x] Карточка активного дня, bottom sheet выбора типа, disabled/action loading,
  локализации и обработка ошибок реализованы.
- [x] После завершения UI намеренно возвращается к той же карточке, что и до
  старта. Отдельная read-only карточка завершённого дня больше не является
  продуктовым требованием.
- [x] Время API корректируется динамическим `DateTime.now().timeZoneOffset`, а
  не жёстким `-5`. Это временная совместимость с backend, который сохраняет
  локальное время со сдвигом, но возвращает строку без timezone.

### Реализовано частично

- [~] Feature flag, status и day types запускаются параллельно, но объединены
  одним `Future.wait`: ошибка одного запроса отменяет применение успешных
  результатов двух остальных.
- [~] Очередь start/end сохраняет попытки и последнюю ошибку, но не различает
  transient и permanent failure и не имеет parked/dead-letter состояния.
- [~] `WorkdayNotifier` использует immutable state, однако сам напрямую
  оркестрирует `RemoteApiService`, `LocalDatabase` и `SharedPreferences`.

### Не реализовано

- [ ] Domain-контракт `WorkdayRepository` и data-реализация, скрывающая API,
  cache и pending queue от presentation/provider слоя.
- [ ] Независимое обновление feature flag, status и day types с частичным
  применением успешных ответов.
- [ ] Парковка неисправимых workday-событий после постоянной 4xx или лимита
  попыток, включая диагностируемую причину и отсутствие бесконечного retry.
- [ ] Тесты reconciliation, permanent/transient retry, resume и частично
  успешного refresh.

Фактический справочник содержит три типа рабочего дня. До изменения backend
клиент должен отображать ответ `/DayType`, а не ожидать пять фиксированных
пунктов.

Детальный порядок исправлений, критерии приёмки и команды проверки находятся в
[`CURRENT_IMPLEMENTATION_GAPS_TODO.md`](CURRENT_IMPLEMENTATION_GAPS_TODO.md).
