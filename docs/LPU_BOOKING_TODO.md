## Подтвержденный API-контракт

- [x] `GET /api/Global` содержит `behavior.prepayment.percent.enable`, `behavior.order.saleprice.edit`, `feature.pharmacy.visits.geo.required`.
- [x] `GET /api/Markups/short` возвращает доступные матрицы предоплаты/типа покупателя.
- [x] `GET /api/Contracts/client/{clientInn}` существует; фактически может вернуть прямой массив, а не `{result: [...]}`.
- [x] `GET /api/Stock/price-list` возвращает складские позиции, binding ID, остатки, цены и фото.
- [x] `POST /api/Pricing/calculate` рассчитывает цены.
- [x] `POST /api/Visits/add` принимает заказный визит.
- [x] В текущем мобильном коде `drug_id` уже строится из binding ID (`drug.id`), а не из dictionary `drug.drug_id`.
- [x] В pricing request поле `income_detail_id` заполняется значением `income_detailing_id` из price-list.

Фактические особенности dev:

- `Stock/price-list?organization_id=...` вернул тот же набор, что запрос без параметра: Swagger не описывает `organization_id`, backend его сейчас игнорирует.
- `Markups/short` на момент проверки содержит 100% и 50% для розницы; 0% и оптовой матрицы нет.
- `Pricing/calculate` с доступной матрицей успешно вернул рассчитанную цену.
- В `price-list` есть `drug.photo.small_url/middle_url`; текущая модель `Drug.imageUrl` это поддерживает.

## Аудит реализации 2026-08-20

Этот раздел отражает фактический код и имеет приоритет над более ранними
галочками выше.

### Реализовано

- [x] Кнопка показывается только для коммерческого ЛПУ:
  `type_id == 2 && is_budget == false`.
- [x] Бронь из ЛПУ открывает существующий order-flow напрямую и сохраняет
  источник `lpu`, не создавая второй mapper payload.
- [x] Расчёт выполняется перед отправкой; в `/Visits/add` уходят рассчитанные
  строки заказа.
- [x] Draft сохраняется локально, а результат отправки различает `sent`,
  `queued` и `rejected`. Постоянная ошибка не переводит экран в success.
- [x] Обычная очередь визитов уже имеет backoff, лимит попыток и парковку
  постоянных ошибок. Повторно реализовывать это в
  `PendingVisitPushService` не нужно.
- [x] Ограничение количества складским остатком и основные поля price-list
  уже используются существующим pharmacy-order flow.

### Реализовано частично

- [~] Доступность опта вычисляется для аптечного flow через legacy
  `/Company/markups`, но ЛПУ открывает диалог без предварительной загрузки
  разрешённых условий. При ошибке аптечный flow также допускает опт по
  умолчанию, что является небезопасным fallback.
- [~] Экран результата корректно сообщает о постановке заказа в очередь, но
  локальные записи истории не получают отдельный визуальный статус
  «Ожидает отправки» из `is_synced/sync_failed`.
- [~] Фото поддерживается моделью и online price-list, однако гарантированное
  файловое кеширование всех фото для offline-каталога не подтверждено.

### Не реализовано

- [ ] Typed источник разрешённых условий из `GET /api/Markups/short` с точным
  соответствием `margin_id`, `prepayment_percent`, `wholesaler`, `retail`.
- [ ] Использование `behavior.prepayment.percent.enable` в UI и ViewModel.
- [ ] Загрузка и выбор договоров ЛПУ через
  `GET /api/Contracts/client/{clientInn}`; сейчас `contract_id` фактически
  остаётся `null`.
- [ ] Передача разрешённых сервером условий в диалог ЛПУ вместо статических
  вариантов `100/0` и разрешённого по умолчанию опта.
- [ ] Явный pending-статус в главной и истории до подтверждённой отправки.
- [ ] Полный набор тестов для коммерческого/бюджетного/null ЛПУ, матриц,
  договоров и offline-pending UI.
